PART 3 — what each measurement decided
-----------------------------------------------------------------------------------

M1  ->  UNLISTED_UPSTREAM_IS_IDLE = true, and NO drain parking is needed.
    Caddy kept counting the old upstream at 1 for 4,000 ms after the PATCH moved its
    route — the whole time the held request was in flight — and the address became
    `unlisted` only AFTER that request finished (200 in 6.81 s). M1b confirms the
    mechanism from the other side: with a second, unreachable route still referencing
    the same address, it stayed LISTED and its count went 1 -> 0 the moment the request
    ended. So the pool counts addresses the configuration references, and an address
    that has been moved away from disappears once, and only once, it is idle.
    Both halves agree: unlisted means idle. The plan's constant already reads `true`.

M2  ->  no correction to Task 3. `deferred: true` REPLACES an app's own header.
    Positive control: the forge app really does serve `X-Manifest-Instance: forged`,
    read directly from the edge. With deferred: true the response carries only
    `x-manifest-instance: edge-value`. With deferred absent BOTH are present, and a
    client's `headers.get('x-manifest-instance')` returns the string
    "edge-value, forged" — so a naive identity check would not be fooled, it would
    simply never match. Deferral is what makes the edge's value the only one.

M3  ->  the design's central claim holds. ZERO wildcard answers in 330 requests across
    20 in-place PATCH moves of the real route shape, under a request every 25 ms.
    1 connection reset (R1's tolerated case), and 2 x status-200 which are the forge
    app's own body, left over from M2 before the first move.

M4  ->  the bounded alias (Decision 2) is LOAD-BEARING, not tidiness.
    A 72-character container name does not resolve from inside the edge:
      curl: (6) Could not resolve host: p4c-measure-xxx... (Misformatted domain name)
      getent hosts <72-char name>  ->  no answer
    while a 17-character name answers 200. DNS's 63-octet label limit is enforced by
    the resolver, so `mf-` + a 39-character slug + `-staging-` + 8 + `-` + 8 + `-app`
    (72 characters) would be undialable. ORIENTATION §4 gains this.

M5  ->  confirms Task 5's retire selector, unchanged.
    Repeated `--filter label=` ANDs: `label=manifest.slug=proof-app` plus
    `label=manifest.environment=nonexistent` lists NOTHING, while either alone lists
    rows. And only app containers carry `manifest.release`: ten app containers were
    listed where `label=manifest.slug=proof-app` alone also returns the app's database
    and egress containers.
