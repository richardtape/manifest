- **Laravel Valet owns this Mac's `.test` TLD, port 53, and ports 80 and 443.** A

- **Caddy binds `127.0.0.2`**, a loopback alias that **does not survive a reboot**.

- **`sudo` cannot prompt from a tool call.** Bundle privileged steps into one script

- **The machine must end up exactly as it started.** Snapshot first.
- **Pre-existing containers that must survive**: `docker-simple-saml-saml-idp-1`,
  `qdrant-local-dev`, `mongodb`, `mongo-express`.
- Ports **7100–7199** were entirely free. In use elsewhere: 6122, 27017, 6333/6334,
  8081, 11434, plus 80/443/53.
- Docker VM memory is **8.32 GB decimal / 7.75 GiB binary** — passes or fails §21's
  "≥8 GB" floor depending on the unit, which is why §21 now states the unit.

### DNS, Docker, Caddy, builds

All still true; `HANDOFF-2026-08-30.md` §4 has them in full. The four that cost the
most time:

- **`--local=/manifest.internal/` is mandatory**, or dnsmasq answers AAAA with
  SERVFAIL and `curl` reports *"Could not resolve host"* while `dig` returns the
  right A record. The most misleading failure in the whole exercise.
- **`--server=127.0.0.11` is mandatory**, or containers lose service names.
- **Caddy admin API: `PUT` inserts, `POST` appends** — and appending puts your route
  behind the wildcard whose `terminal: true` swallows it.
- **Offline builds need base images in the local registry.** BuildKit re-resolves
  `FROM` every build and cannot see the daemon's cache.

### AI — new from S3

- **LiteLLM 1.98.0 serves admin and proxy traffic on ONE port.** There is no admin
  port to firewall. Confinement is per-key `allowed_routes`.
- **Ollama 0.33.2 on the host, reached via `extra_hosts: host.docker.internal:host-gateway`.**
  Twelve models present. `nomic-embed-text` is 768-dimensional.
- **Most models on this machine are *thinking* models, and that breaks streaming
  silently.** `qwen3.5:4b` asked to count to five produced **1,677 reasoning frames
  and zero content frames** — the app sees no chunks, an empty string and no error.
  Raising `max_tokens` does not help. `ministral-3:latest` streams correctly.
- The spike needed **no `sudo` and no host changes at all** — two containers.

## 5. The three S3 findings that will bite P4 if they are forgotten

They are P4's problem, not P1's, but they are the kind of thing that gets lost
between plans, and **all three fail silently.** Full detail in `S3-findings.md`.

1. **Every LiteLLM key needs `allowed_routes`.** Without it, an app key whose
   `user_id` came from `/user/new` can call `/key/generate` and mint a child key
   **that survives revocation of its parent**. §11's "the agent key dies with the
   sandbox" is not true of `/key/delete` alone. Agent keys also get a `duration` TTL.
2. **Every `embed()` call needs `encoding_format: 'float'`.** Without it the OpenAI
   SDK's base64 default meets LiteLLM's Ollama path, and the toolkit returns **192
   near-zero values where 768 floats belong** — no error, every other assertion
   green. §16 asserts the dimension for this reason.
3. **The LiteLLM `user` must be `hash(puid ‖ project ‖ environment)`.** End-user
   budgets are global, so a bare PUID hash means a student who exhausts their budget
   in one course tool is refused by every other Manifest app.

Also: **pin `store_prompts_in_spend_logs: false` in `config.yaml`** and never ship
`--detailed_debug`. The default is safe, but if the key is absent from the YAML the
admin UI's runtime value wins, and one click starts retaining student prompts.

## 6. What P1 is, and how to write it

Read the roadmap's P1 section first; this is the summary. **P1 is 1a-i, the local
substrate** — §21's platform inventory as running infrastructure, plus
`make seed / up / reset / doctor`. It is configuration and shell, not TypeScript,
and it is the one plan whose content a spike dictates almost line by line.

**Its demo, which is also C1's bar:** `make seed && make up && make doctor` on a
**second machine**, offline after seeding, serving a placeholder over trusted HTTPS
at a `manifest.internal` name that resolves identically from the host browser and
from inside a container.

**Use `superpowers:writing-plans`.** Every plan in this repo carries the required
header, its own file-structure map, and bite-sized TDD steps with real content. Read
`plans/2026-08-29-p2-control-plane-spine.md` for the house style — it is the
worked example, and it is long on purpose.

**The rule that matters most:** *no plan may contain a step standing in for a spike
result.* That was the failure an earlier session made. Every fact P1 needs now
exists in a findings note; if you find yourself writing "determine whether…", stop
and go read the note.

### What P1 must carry, at minimum

- dnsmasq with S7's two-process split-horizon design, **verbatim** — the flags are
  not optional and the findings explain why each one is there
- the custom `xcaddy` image (rate-limit + Coraza). **The versions are pinned
  together**: Coraza v2.6.0 *requires* Caddy v2.11.4 and xcaddy refuses any other
- the `127.0.0.2` loopback alias, and **an answer to who re-adds it after a reboot**
  (§8 below — this is still open)
- Postgres with its three databases; the registry; Verdaccio; the egress proxy
- LiteLLM with `STORE_MODEL_IN_DB`, the pinned logging setting, and no
  `--detailed_debug`
- Ollama as a host application, with **a named non-thinking chat model** and an
  embedding model that `make seed` pulls and `make doctor` checks
- CA trust in **three** places — macOS keychain, container trust stores, and the host
  Node processes. `security add-trusted-cert` **prompts for a password even under
  `sudo`**; do not write a plan that pretends otherwise
- `make doctor` checks: Docker running, VM memory **with the unit stated**, Ollama up
  with the required models, resolver file installed, CA trusted, ports free, disk,
  architecture, `/health/readiness` returning `db: connected`, zero unhealthy LiteLLM
  deployments, and **a streamed completion returning non-empty content**
