  1. held the socket open,
  2. been refused 403 by the admin API,
  3. printed "unrelated route inserted" ANYWAY — the .then() does not check r.ok

  4. reached the 20s timeout and printed "SURVIVED 20s, still open",
  5. and Section 8's item would have closed as "measured, and not a problem in
     Phase 1" — the OPPOSITE of the truth — on a config reload that never happened.

The socket would have survived because NOTHING EVER RELOADED THE EDGE.

This is precisely the shape ORIENTATION section 4 and 9 keep naming: a control
that cannot fail, reporting a green that means nothing. It is recorded here
because the correction is not "use curl": it is ASSERT THE ADMIN CALL'S STATUS.
The client used for this measurement does:
    if (r.status !== 200) { console.log('ADMIN PUT FAILED ... MEASUREMENT INVALID'); process.exit(3) }
and refuses to report SURVIVED at all unless a reload is known to have happened:
    if (!reloadedAt) { console.log('never reloaded — MEASUREMENT INVALID'); process.exit(3) }
