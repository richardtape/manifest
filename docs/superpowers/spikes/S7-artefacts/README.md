# S7 artefacts — the parts of the spike that survive

`docs/superpowers/spikes/START-HERE.md` says spike code is thrown away except the
artefacts named under *What survives the spike*. These are those, made runnable
rather than left as prose, because **S1 depends on them** — its checklist needs
`--dns` from S7, Caddy's admin API, the registry and a routed name reachable from
both host and container.

**These are spike scaffolding, not P1 code.** P1 rewrites them as Compose plus a
Makefile. Do not polish them; do reuse them.

| File | What it is |
|---|---|
| `up.sh` | Brings up the platform network, both dnsmasq processes and the custom Caddy. Safe to re-run. Detects whether the `127.0.0.2` alias exists and binds accordingly. |
| `host-setup.sh` | **The three `sudo` steps.** Run *after* `up.sh` has produced `ca/manifest-root.crt`, then re-run `up.sh`. |
| `host-undo.sh` | Reverts all three. Names nothing belonging to Laravel Valet. |
| `down.sh` | Removes only what the spike created. |
| `Dockerfile.caddy` | The `xcaddy` build — rate-limit + Coraza. Versions are pinned *together*; read the comment before bumping either. |
| `Dockerfile.dnsmasq` | alpine + dnsmasq + `bind-tools`. |
| `Caddyfile` | §23's three platform zones, one wildcard certificate each. |
| `etc-resolver-manifest.internal` | Goes to `/etc/resolver/manifest.internal`. |

## Order matters

```
bash up.sh                 # container half works immediately; writes ca/manifest-root.crt
sudo bash host-setup.sh    # human runs this — sudo cannot prompt from a tool call
bash up.sh                 # re-run: moves Caddy onto 127.0.0.2:443
```

`up.sh` prints the exact check commands for both host and container.

## Verified on 2026-08-29

Both container-side checks pass straight from these files:

```
$ docker run --rm --network manifest-spike --dns 10.89.0.53 \
    -v $PWD/ca/manifest-root.crt:/ca.crt:ro curlimages/curl:8.11.1 \
    --cacert /ca.crt -sS https://console.manifest.internal/
manifest-spike OK host=console.manifest.internal scheme=https remote=10.89.0.2
```

`ca/` is generated by `up.sh` and deliberately not committed — the CA root is
regenerated per Caddy data volume, so a stale committed copy would be actively
misleading.

## When you are finished

The machine must end up as it started — a standing requirement from Rich:

```
bash down.sh
sudo bash host-undo.sh
```

Either order works. `host-undo.sh` removes the CA by common name, so it does not
need `ca/manifest-root.crt` to still exist — an earlier version did, and printed
`Error reading file ca/manifest-root.crt` when `down.sh` had already deleted it.
