## 4. What is already known — do not spend time rediscovering this

`START-HERE.md` §6 has a list like this. **Ignore it and use this one instead**: two
of its entries are now wrong, and everything below was verified on 2026-08-29.

### The machine

- **Laravel Valet owns this Mac's `.test` TLD, port 53, and ports 80 and 443.**
  `START-HERE.md` §6 says `/etc/resolver/test` points at "a nameserver that is not
  listening". **That is wrong.** A Homebrew dnsmasq 2.91 runs as `nobody` on
  `127.0.0.1:53` with `address=/.test/127.0.0.1`, and the nginx on 80/443 is Valet's.
  **Never touch any of it** — Rich needs Valet working, and other UBC developers run
  it too.
- **The zone is `*.manifest.internal`**, not `*.manifest.test`. ICANN-reserved.
  The resolver file is scoped to `manifest.internal`, **never all of `.internal`** —
  Docker's own `host.docker.internal` lives in that TLD.
- **Caddy binds `127.0.0.2`**, a loopback alias, so Valet keeps `127.0.0.1:443`.
  The alias **does not survive a reboot**. If binds fail with
  `can't assign requested address`, that is the cause.
- **`sudo` cannot prompt from a tool call.** You will get
  `sudo: a terminal is required to read the password`. Bundle privileged steps into
  one script and ask Rich to run `! sudo bash <path>` in his terminal. **Ask before
  anything needing sudo** — that is a standing instruction.
- **The machine must end up exactly as it started.** Snapshot before you change
  anything; `host-undo.sh` and `down.sh` exist for this. Rich confirmed the previous
  undo was clean.
- Ports in use by *other* things: **6122** (standalone `docker-simple-saml`),
  **27017** (mongodb), **6333/6334** (qdrant), **8081** (mongo-express), **11434**
  (Ollama), plus 80/443/53. The **7100–7199** block was entirely free.
- Docker VM memory is **8.32 GB decimal / 7.75 GiB binary** — passes or fails §21's
  "≥8 GB" floor depending on the unit. Host: 36 GiB RAM, 12 cores, 173 GiB free.
- **Pre-existing containers that must survive**: `docker-simple-saml-saml-idp-1`,
  `qdrant-local-dev`, `mongodb`, `mongo-express`.

### Docker and DNS behaviour that will cost you a morning

- **`--address` is global to a dnsmasq *process*, not per-interface.** Verified. That
  is why there are two dnsmasq containers, not one with two listeners.
- **`--local=/manifest.internal/` is mandatory.** Without it dnsmasq answers AAAA
  with **SERVFAIL** instead of NODATA, and musl and glibc both treat SERVFAIL on
  either half of a dual-stack lookup as total failure. The symptom is
  `curl: (6) Could not resolve host` **while `dig +short` returns the correct A
  record.** This is the single most misleading failure in the whole spike.
- **`--server=127.0.0.11` is mandatory.** Without it, `--no-resolv` makes dnsmasq
  authoritative for everything and containers lose Docker service names *and*
  external resolution.
- **On Docker Desktop, `--dns` sets the *upstream* for Docker's embedded resolver
  rather than replacing it.** `/etc/resolv.conf` still says `nameserver 127.0.0.11`
  with `# ExtServers: [<yours>]`. Good news: container-to-container service names
  survive. Do not conclude `--dns` is being ignored.

### Caddy

- The custom build is **Caddy v2.11.4 + `caddy-ratelimit@v0.1.0` +
  `coraza-caddy/v2@v2.6.0`**. **Coraza pins the Caddy version** — it *requires*
  2.11.4 and xcaddy refuses any other. `caddy-ratelimit` has exactly **one**
  published release, ever.
- **Admin API route ordering:** `PUT /config/apps/http/servers/srv0/routes/0`
  **inserts**; `POST` to the same path **appends**, which puts your route *behind*
  the wildcard route whose `terminal: true` then swallows it. S1 confirmed `PUT` is
  the right call and that route churn drops no in-flight requests.
- Certificates for names allocated at runtime are issued on demand and verify with
  no intervention.

### SimpleSAMLphp (S2's territory — relevant if you touch identity)

- `docker-php-ext-install pdo_pgsql` **also needs `libpq-dev`**.
- The `pdo` entry in `metadata.sources` carries **no** connection details — the
  handler ignores them and reads the global `database.*` block.
- **`database.*` and `store.sql.*` are different subsystems.** The latter is the
  session store. Proving one works proves nothing about the other.
- **`core:AttributeLimit` is not in the default chain**, and a row with a missing or
  empty `attributes` list **releases everything**.
- With the same entityID in both a flatfile and the SQL store, **the first matching
  `metadata.sources` entry wins** — a stale file silently shadows a SQL row.
- **UBC Shibboleth sends OID**, confirmed: `tlef-biocbot` works against staging and
  production with no bridge, and the OID is its only reachable key for
  `ubcEduCwlPuid`.

### Builds and containers (from S1 — read `S1-findings.md` before touching these)

- **Rootless BuildKit works**, but buildx's `docker-container` driver wraps the
  rootless image in a **`--privileged`** container, which §12 forbids. Run
  `moby/buildkit:v0.32.2-rootless` as a plain non-privileged container and attach
  `--driver remote docker-container://<name>`. It must listen on its **default unix
  socket**; `--addr tcp://…` makes the transport hang.
- **`buildkitd.toml` needs `[dns] nameservers = ["127.0.0.11"]`** or `RUN` steps
  cannot resolve Docker service names — BuildKit writes its own `resolv.conf`.
- **Offline builds need base images in the local registry.** BuildKit re-resolves
  `FROM` on every build; the daemon's cache is invisible to the rootless worker.
- **A container on an `--internal` network loses its published ports.** Dual-home the
  registry and mirror; only the builder stays internal-only.
- **`docker push localhost:7107/…` resolves to `::1` and times out.** Use `127.0.0.1`.
- **User-namespace remapping silently does nothing** on Docker Desktop. Every other
  §12 hardening flag genuinely enforces.
- **A host process cannot reach container IPs**, so health checks go through the edge.
- **Restarting Caddy discards all runtime routes.** Route changes under load are
  safe though: 0 failures in 400 requests across 12 add/remove cycles.
